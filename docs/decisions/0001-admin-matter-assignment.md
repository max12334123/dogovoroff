# ADR 0001: атомарное назначение дела администратором

Статус: принято в коде; применение миграции к Production требует отдельного подтверждения.

## Контекст

Клиент регистрируется самостоятельно, но не должен получать доступ к делу без назначения.
Администратору нужен интерфейс в `/staff`, при этом клиентский код не должен получать
`service_role` или доступ к каталогу email.

## Решение

- Администратор вводит полный подтверждённый email клиента.
- Server action повторно проверяет текущую сессию и роль `admin` в выбранной организации.
- PostgreSQL RPC ещё раз проверяет роль, находит только точное совпадение email и в одной
  транзакции создаёт дело, клиентское назначение, необязательное назначение сотрудника и
  первый этап.
- Отдельная RPC возвращает только UUID, отображаемое имя и роль сотрудников организации;
  email из базы не возвращается.
- Обе RPC закрыты для `public` и `anon`, не используют пользовательские metadata Auth для
  авторизации и не требуют секретного ключа Vercel.

## Последствия

- При ошибке не остаётся частично созданного дела.
- Администратор может проверить существование известного ему точного email; эта возможность
  недоступна клиентам и юристам.
- Назначить можно только уже зарегистрированный и подтвердивший email аккаунт.
- Назначение ролей сотрудников пока остаётся административной операцией Supabase Dashboard.
