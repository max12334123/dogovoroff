# Личный кабинет: MVP-фундамент

## Текущий объём

Маршрут `/cabinet` теперь защищён Supabase Auth и получает назначенные дела из базы данных через RLS. Клиент может:

- войти или зарегистрироваться по подтверждённому email без пароля;
- увидеть активное и завершённое дело, если оно назначено аккаунту;
- открыть спокойный пустой кабинет до назначения первого дела;
- понять текущий этап и следующий требуемый шаг;
- переключаться между обзором, делами, документами и сообщениями;
- проверить локально выбранный файл по типу и размеру;
- подготовить черновик сообщения в памяти текущей страницы;
- перейти к новому AI-разбору.

Главная страница содержит ссылку на кабинет в desktop- и mobile-навигации. Маршрут исключён из индексации поисковыми системами.

## Граница текущего MVP

Аутентификация, чтение дел, этапов, событий, документов и сообщений уже выполняются через Supabase с серверными cookie и RLS. Загрузка, сохранение и отправка файлов и сообщений пока остаются локальным прототипом: файл проверяется только в браузере и не покидает устройство, черновик сообщения существует только в состоянии открытой страницы.

До реализации серверных операций записи маршрут нельзя использовать как рабочий канал обмена юридическими документами.

## Следующий продуктовый этап

Для рабочего кабинета необходимо реализовать и отдельно проверить:

1. способ входа и восстановления доступа;
2. модель ролей «клиент / юрист / администратор»;
3. таблицы дел, участников, событий, документов и сообщений;
4. серверную авторизацию и политики изоляции данных;
5. приватное файловое хранилище и временные ссылки;
6. аудит доступа и безопасные уведомления без чувствительных данных;
7. удаление и экспорт данных клиента.

Добавление Supabase или другого сервиса авторизации и хранения должно выполняться только после проверки схемы прав и отдельного подтверждения production-зависимости.
